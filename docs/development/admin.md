# 管理者ログインと店舗登録・編集

[概要](../../README.md) · [文書一覧](../README.md) · [開発手順](README.md)

## ローカルの設定と起動

一般利用者はログイン不要。管理者も`/admin-login`を開いてGoogle認証する。ログイン成功後は`/`へ移動する。ホームにはログインボタンを表示しない。

`.env`または`.env.local`に次を追記する。Mapsキーなど既存の設定を上書きしない。

```dotenv
VITE_USE_FIREBASE_EMULATORS=true
ADMIN_GOOGLE_EMAIL=admin@example.test
```

```sh
pnpm emulators
pnpm seed
pnpm dev
```

開くURLは開発サーバーに表示されるものを使用する。ポートが5174なら`http://127.0.0.1:5174/`。ポップアップを開けるChromeなどのブラウザで操作する。アプリ内ブラウザによっては認証の子ウィンドウを扱えない場合がある。

`pnpm seed`は`.env`→`.env.local`→シェルの順で値を上書きして解決する。メールを小文字化し、前後の空白を除いて形式検証してから書き込む。不正な形式や許可しない接続先なら、投入前に失敗する。

管理者メールを非公開設定`_settings/admin`へ保存し、指定時だけ作成・更新する。シードは店舗データを作成・変更しない。

## Google模擬ログイン

1. `/admin-login`の「Googleでログイン」を押す。
2. Auth Emulatorの「Auth Emulator IDP Login Widget」で、環境変数と同じメールのテストアカウントを選ぶ。まだ存在しなければ同じメールでテストアカウントを追加する。
3. 認証と権限照合が成功すると、ヘッダーに「管理者」「ログアウト」、未登録のコンビニ詳細に「トイレ情報を登録」が表示される。

実際のGoogleログイン画面やパスワード入力は使わない。Auth Emulatorの模擬画面はGoogleアカウントの所有を保証しないため、ローカル開発でだけ使う。クラウドプロジェクトやGoogleログイン有効化の操作は不要。[Firebaseの公式説明](https://firebase.google.com/docs/emulator-suite/connect_auth)

Googleプロバイダー・メール確認済み・許可メールの一致を確認する。設定がない場合や対象外メールでは管理者になれず、対象外アカウントはサインアウトする。認証・権限確認中と接続失敗時も閲覧は継続できる。キャンセル・ポップアップブロック・認証失敗は画面に案内する。

同じタブの再読み込みではログインを維持し、タブを閉じると終了する。「ログアウト」で閲覧モードへ戻る。

## 店舗の登録・編集

Places APIで取得した未登録のコンビニをピンまたは一覧から選び、「トイレ情報を登録」でフォームを開く。Place ID・店名・住所・座標を引き継ぐ。任意地点からの登録や、Place IDのない店舗登録はできない。

既存店舗は一覧・ピンから詳細を開き「店舗を編集」を押す。shadcn/uiのDialogに現在の情報を表示し、スマホでもフォーム部分をスクロールして操作できる。

- 店名・チェーン名・住所は必須。店名と住所はPlacesの値を初期入力する。緯度経度は選択した店舗の位置を使い、フォームでは変更できない。
- 条件付き利用では条件文を必須にする。
- 設備数は空欄なら不明、0なら設備なし。非負整数だけを許可する。
- 最終確認日は「未確認」または日付を指定する。日付は日本時間の0時として保存する。
- geohashは保存時に座標から生成する。作成更新日時はサーバー時刻で記録する。
- 新規店舗にはPlace IDを必須とし、店舗とPlace IDの紐付けを同時に保存する。架空サンプルは登録できない。

保存中は入力・閉じる操作と二重送信を抑制する。失敗時は入力を保持して再試行できる。新規フォームで確保したIDを再利用して重複作成を防ぎ、既に別内容で保存されていた場合や編集中に更新された場合は上書きせず、一覧の更新と編集し直しを案内する。未保存のフォームを閉じる場合は破棄確認を表示する。

保存後は店舗情報だけを再取得して詳細へ戻る。地図全体は再読み込みしない。100件上限外の新規店舗は保存成功と一覧非表示の理由を案内する。再取得が失敗した場合も、保存済みであることと手動更新を案内する。

## 管理者の変更と権限

`ADMIN_GOOGLE_EMAIL`を変更して`pnpm seed`を再実行する。既存の店舗情報は保持し、管理者設定だけを切り替える。旧管理者の保存はRulesで拒否する。変数の未指定・空文字は既存設定を維持するため、値を消すだけでは権限を失効させない。

許可メール設定は一般公開せず、クライアントからの設定変更は管理者も禁止。店舗の読み取りは全員に許可し、管理者だけに作成・更新を許可する。Place IDの紐付けは店舗との同時作成だけ許可し、更新・削除は禁止する。店舗削除・サブコレクション・その他のコレクションは禁止する。詳細は[認証とアクセス制御](../architecture/security.md)を参照する。

`VITE_USE_FIREBASE_EMULATORS=false`では店舗取得・認証・登録編集を無効化する。実Google認証、クラウド接続、削除は今回の範囲に含めない。Places検索はEmulator設定と独立して利用できる。

## グレーのコンビニから登録する

未登録と確認できたコンビニのピンを開き、「トイレ情報を登録」からフォームへ進む。保存後は登録済みピンへ切り替わる。登録確認中・取得失敗時は登録操作を表示せず、接続確認・更新後に操作する。

座標だけで登録した旧店舗と架空サンプルは削除対象とし、既存店舗への手動紐付け機能は設けない。[整理手順](sample-data.md#旧データの整理)を参照する。
