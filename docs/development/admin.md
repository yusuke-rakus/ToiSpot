# 管理者ログインと店舗登録・編集

[概要](../../README.md) · [文書一覧](../README.md) · [開発手順](README.md)

本書はローカルEmulatorの操作手順。本番のユーザー事前登録、新規登録禁止、管理者指定・交代は[Firebaseへのデプロイ手順](../operations/deployment.md)を参照する。本番での動作確認は別途必要。

## ローカルの設定と起動

一般利用者はログイン不要。管理者は`/admin-login`からメールアドレス・パスワードで認証し、成功後は`/`へ移動する。ホームにはログインボタンを表示しない。本番も同じフォームを使うが、アカウントとパスワードは別に管理する。

`.env`または`.env.local`に次を追記する。Mapsキーなど既存の設定を上書きしない。

```dotenv
VITE_USE_FIREBASE_EMULATORS=true
ADMIN_EMAIL=admin@example.test
ADMIN_PASSWORD=local-development-only
```

上記パスワードはローカル用の例。本番では使用しない。旧`ADMIN_GOOGLE_EMAIL`を新しい2項目に置き換える。

```sh
pnpm emulators
pnpm seed
pnpm dev
```

開くURLは開発サーバーに表示されるものを使用する。ポートが5174なら`http://127.0.0.1:5174/admin-login`。ポップアップは使用しない。

`pnpm seed`は`.env`→`.env.local`→シェルの順で値を上書きする。メールは前後の空白を除去して小文字化し、パスワードは空白を含め入力どおり扱う。メール形式とパスワード6〜4096文字を検証する。両方が未指定・空文字なら既存の管理者設定を保持する。片方だけの指定、旧変数だけの指定、不正形式、許可しない接続先は投入前に失敗する。認証情報には`VITE_`を付けず、Gitへ追加しない。

接続先はSDK初期化前に`demo-toilet-map`、Firestoreはローカル18081番、Authはローカル19090番に限定する。Authユーザーを作成し、そのUIDを非公開設定`_settings/admin`の`uid`へ保存する。同じメールで再実行するとUIDを維持して指定パスワードを適用する。無効化済みユーザーは再有効化せず、シードを中断する。メール・パスワード・トークン・生のSDKエラーは出力しない。

シードはテスト店舗7件とPlace IDの紐付けの不足分も投入するが、既存店舗と編集内容は上書きしない。[店舗データの手順](sample-data.md)を参照する。AuthとFirestoreの処理は一括トランザクションではないため、途中失敗時は接続状態を直して同じ設定で再実行する。

## メール・パスワードでログイン

1. `/admin-login`へアクセスする。
2. `ADMIN_EMAIL`と`ADMIN_PASSWORD`に指定した値を入力し、「ログイン」またはEnterで送信する。
3. 認証とUID照合が成功するとホームへ移動し、「管理者」「ログアウト」と店舗の登録・編集操作が表示される。

認証情報の誤り、無効アカウント、試行回数超過、通信失敗は画面に案内する。送信完了後はパスワード入力を消去する。失敗時はメールを保持し、パスワードを再入力して試行できる。

管理者判定はUID一致と`password`プロバイダーを要求する。メール確認済み操作は不要。同じメールでも別UIDやGoogleログインでは編集できない。旧`{ email }`設定は利用できないため、移行後にシードを実行する。対象外アカウントはサインアウトし、認証・権限確認中と接続失敗時は閲覧のみ可能。

同じタブの再読み込みではログインを維持し、タブを閉じると終了する。「ログアウト」で閲覧モードへ戻る。アプリ内に新規登録・パスワード再設定画面は設けない。

## 店舗の登録・編集

Places APIで取得した未登録のコンビニをピンまたは一覧から選び、「トイレ情報を登録」でフォームを開く。Place ID・店名・住所・座標を引き継ぐ。任意地点からの登録や、Place IDのない店舗登録はできない。

既存店舗は一覧・ピンから詳細を開き「店舗を編集」を押す。shadcn/uiのDialogに現在の情報を表示し、スマホでもフォーム部分をスクロールして操作できる。

- 店名・コンビニの種類・住所は必須。店名と住所はPlacesの値を初期入力する。緯度経度は選択した店舗の位置を使い、フォームでは変更できない。
- 貸出状況は「利用可」「利用不可」の2択から明示的に選ぶ。利用条件や補足は備考に入力する。
- 利用可の場合だけ設備数を入力する。空欄なら不明、0なら設備なし。非負整数だけを許可する。
- 貸出状況を切り替えてもフォーム内の設備入力は保持する。利用不可で保存すると設備数をすべてnullにし、非表示の設備入力は検証しない。設備区分と最終確認日の入力・保存項目は持たない。
- geohashは保存時に座標から生成する。作成更新日時はサーバー時刻で記録する。
- 新規店舗にはPlace IDを必須とし、店舗とPlace IDの紐付けを同時に保存する。架空サンプルは登録できない。

保存中は入力・閉じる操作と二重送信を抑制する。失敗時は入力を保持して再試行できる。新規フォームで確保したIDを再利用して重複作成を防ぎ、既に別内容で保存されていた場合や編集中に更新された場合は上書きせず、一覧の更新と編集し直しを案内する。未保存のフォームを閉じる場合は破棄確認を表示する。

保存後は店舗情報だけを再取得して詳細へ戻る。地図全体は再読み込みしない。100件上限外の新規店舗は保存成功と一覧非表示の理由を案内する。再取得が失敗した場合も、保存済みであることと手動更新を案内する。

## 管理者の変更と権限

`ADMIN_EMAIL`・`ADMIN_PASSWORD`を新管理者の値に変更して`pnpm seed`を再実行する。既存店舗を保持し、許可UIDを切り替える。設定変更後、旧UIDの保存はRulesで拒否する。旧Authユーザーは自動削除しない。必要に応じてEmulator UIで無効化する。変数を消すだけでは権限を失効させない。

ローカルのパスワードを忘れた場合は、同じメールと新しいパスワードを設定して再シードする。無効ユーザーの状態変更はEmulator UIで明示的に行う。

管理者設定は一般公開せず、クライアントからの設定変更は管理者も禁止。店舗の読み取りは全員に許可し、管理者だけに作成・更新を許可する。Place IDの紐付けは店舗との同時作成だけ許可し、更新・削除は禁止する。店舗削除・サブコレクション・その他のコレクションは禁止する。詳細は[認証とアクセス制御](../architecture/security.md)を参照する。

`VITE_USE_FIREBASE_EMULATORS=false`とFirebase設定4項目が揃うと、本番のメール・パスワード認証とクラウドの取得・登録編集を利用できる。本番のユーザー登録・管理者UID設定・新規登録禁止はConsoleの管理操作で行う。ローカルの環境変数とシードでは本番設定を変更しない。Places検索はEmulator設定と独立して利用できる。

## グレーのコンビニから登録する

未登録と確認できたコンビニのピンを開き、「トイレ情報を登録」からフォームへ進む。保存後は登録済みピンへ切り替わる。登録確認中・取得失敗時は登録操作を表示せず、接続確認・更新後に操作する。

座標だけで登録した旧店舗と架空サンプルは削除対象とし、既存店舗への手動紐付け機能は設けない。[整理手順](sample-data.md#旧データの整理)を参照する。
