# 検証・受け入れ条件

[概要](../../README.md) · [文書一覧](../README.md)

仕様確定時にテストケースへ落とし込み、実装後に結果を記録する。以下は製品全体の受け入れ条件であり、個々の実装済み範囲と結果は末尾に記録する。

## 権限とデータ

- 未ログイン利用者が公開情報を閲覧できる。
- 未ログイン利用者と管理者以外の認証ユーザーは、直接SDKを操作しても登録・更新・削除できない。
- 管理者が保存した内容が再取得後も一致する。
- 不正な設備数・座標・区分、許可しないフィールドをDB側でも拒否する。
- 不明と0を区別でき、男女別・共用・混在・一部未確認のケースを誤表示しない。
- 削除・非公開・閉店の権限と挙動が、決定した仕様に一致する。

## 検索と画面

- 位置情報を拒否・取得失敗しても代わりの操作で検索できる。
- ピンと一覧が同じ店舗を示し、範囲外候補と重複を除外できる。
- 件数上限や一部結果の省略を明示し、不完全な検索結果を全件として扱わない。
- 通信失敗、認証失敗、Mapsロード失敗、検索結果なしを区別して案内する。
- 保存失敗時に入力を保持し、再試行で意図しない重複登録を生まない。
- スマホでフォーム入力、地図操作、詳細閲覧ができ、帰属表示を遮らない。
- フォームのラベルとエラーが関連付き、キーボード操作とダイアログのフォーカスが適切に動く。
- 管理画面などのURLを直接開ける。URLの検索条件を検証し、戻る・進む操作が決定した検索仕様に一致する。

## 費用と運用

- 詳細の開閉や絞り込みで不要な地図再ロード・DB再取得が発生しない。
- Queryによる画面復帰・再接続時の取得、失敗時の自動再試行、Routerのプリロードが設定どおり抑制される。明示的な再検索と保存成功後のキャッシュ更新は反映される。
- RouterとQueryが同じFirestoreデータを二重取得せず、取得結果が古い検索条件の画面に混ざらない。
- 想定店舗数と検索回数で、地図ロード・読み取り・転送量を計測する。
- キー制限、利用上限、通知先を確認する。上限到達時の画面はモックなどで検証し、負荷をかけて実際の無料枠を使い切らない。
- 公開前に最新料金とHosting転送枠の記載差を確認する。
- データ復旧と公開バージョンの切り戻しを、決定した手順で実施できる。
