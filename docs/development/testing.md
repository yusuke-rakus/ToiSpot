# テスト方針

[概要](../../README.md) · [開発手順](README.md) · [文書一覧](../README.md)

自動テストは、検索・保存・権限などの機能の回帰を防ぐために書く。各テストでは、入力や操作によって変わるデータ、状態、遷移先、外部サービスへの要求を確認する。

## 自動テストの対象

| テスト                   | 場所                     | 確認すること                                                                                                                                               |
| ------------------------ | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vitest                   | `src/**/*.test.{ts,tsx}` | 入力検証、検索・絞り込み、データ変換、取得の上限・キャッシュ、競合・中断・再試行。画面との連携は、操作から送信される値や変更後のデータ・状態で確かめる。   |
| Firestore・Auth Emulator | `tests/rules/`           | 公開データの読み取り、申請の公開範囲、認証と管理者権限、保存時の入力制約、店舗・Place ID紐付け・申請承認の原子性。                                         |
| Playwright               | `tests/e2e/`             | 場所の選択から周辺検索、店舗選択から経路案内、登録・修正申請の審査と承認後の公開など、機能をまたぐ操作。PC・スマホで操作経路が異なる場合は両方を確認する。 |
| Node.js                  | `scripts/*.test.mjs`     | 配信サーバーのHTTP応答や直接URLでのアクセス、デプロイ用スクリプトの入力検証・更新条件・機密値の秘匿。                                                      |

特に、次の回帰を優先する。

- 検索範囲・結果・絞り込みの整合性、現在地取得に失敗したときの代替検索、古い応答による上書きや不要なAPI呼び出しの防止。
- 入力値の正規化と設備数の `0`・`null` の区別、保存失敗からの再試行、二重送信の抑止。
- テーマ設定の保存と別タブへの同期。切り替え時も選択した店舗や編集中の入力を保持し、検索を繰り返さないこと。
- 管理者だけが行える操作、ログアウト後の非公開キャッシュ破棄、申請の競合時に公開情報を上書きしないこと。Firestoreの権限と永続化はEmulatorで検証する。

## ケースの書き方

- 仕様に基づき、正常系と影響の大きい境界値、失敗、権限、競合を選ぶ。最小の層で検証し、複数の機能をつなぐときに起こる回帰は結合テストやE2Eで押さえる。
- 画面は機能を使う入口として操作する。ロールやラベルで操作対象を特定し、保存データ、選択された店舗、URL、呼び出し回数などを確認する。配色・配置・アイコン・フォーカス位置・スクロール・案内文言は手動確認の対象とする。
- Maps・Places・位置情報はスタブを使う。Firestoreの永続化・権限はテスト専用の `demo-toilet-map-tests` を使い、E2EではFirestore・認証の境界を差し替える。テストは実キー・本番データ・実際の現在地に依存せず、応答順序や待機時間はスタブやテスト用タイマーで制御する。

## 実行と手動確認

変更後は `pnpm check` を実行する。画面をまたぐ操作を変更した場合は `pnpm test:e2e`、Firestoreの権限・永続化を変更した場合は `pnpm test:rules` または `pnpm test:rules:docker`、配信・デプロイスクリプトの変更時は対応するNode.jsのテストを実行する。コマンドと実行環境は[開発手順](README.md#検証コマンド)を参照する。

画面の変更時は、関係する画面幅・状態で操作し、文言、レイアウト、キーボード操作とフォーカス、入力欄とエラーの関連付け、Mapsの帰属表示を確認する。実キーでの動作、API利用量・利用上限、データ復旧と切り戻しは[料金と利用上限](../operations/costs.md)と[公開手順](../operations/deployment.md)を参照する。

導入時や過去の機能追加時の結果は[過去の検証記録](testing-history.md)を参照する。
