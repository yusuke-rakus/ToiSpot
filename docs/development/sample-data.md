# Firestoreの店舗データと旧データの整理

[概要](../../README.md) · [文書一覧](../README.md) · [開発手順](README.md)

## 起動と登録

Node.js 24系、pnpm 12.16.1、起動済みのDockerを用意する。`.env`または`.env.local`にMaps APIキーと`VITE_USE_FIREBASE_EMULATORS=true`を設定する。既存の環境ファイルを上書きしない。

```sh
pnpm emulators
pnpm seed
pnpm dev
```

`pnpm seed`は現在の万願寺周辺のテスト店舗7件を`stores`へ、Place IDの紐付けを`placeLinks`へ投入する。データは`scripts/data/stores.json`に保存してあり、空のEmulatorでも再現できる。`ADMIN_GOOGLE_EMAIL`を指定した場合は管理者メール設定も作成・更新する。

店名・住所・座標・Place IDは2026年11月3日のPlaces検索時の情報で、貸出状況・設備数は動作確認用の架空設定。備考の「テストデータ・実地未確認」を保持する。利用不可の設備数はすべてnullとし、設備区分・最終確認日・利用条件専用項目は保存しない。旧来の架空店舗6件とは別で、実在のPlace IDを持ち、`isSample`はfalseとする。

固定IDで不足分だけをトランザクション内で作成し、既存店舗の編集内容・日時を変更しない。既存店舗の紐付けだけが欠けている場合は補完する。Place IDが別店舗へ紐付いている場合や、同じ固定IDに異なるPlace IDの店舗がある場合は、その店舗の投入を見送り、競合件数を表示する。無関係な店舗・管理者設定・Authアカウントは削除しない。

対象は以下の7店舗。地図で確認する際は万願寺周辺へ移動し、「この周辺を検索」を押す。

- セブン-イレブン 日野石田２丁目店
- ローソン 日野石田一丁目店
- セブン-イレブン 日野万願寺６丁目店
- ファミリーマート 日野万願寺店
- セブン-イレブン 日野万願寺２丁目店
- セブン-イレブン 日野税務署前店
- ローソン・スリーエフ 日野下田店

管理者がPlacesのコンビニを選択し、「トイレ情報を登録」から登録する。Place ID・店名・住所・座標を引き継ぎ、貸出状況・利用可の設備数・備考を入力する。座標は手入力で変更できない。登録済み店舗の編集は詳細から行う。[管理者機能](admin.md)を参照する。

## 旧データの整理

リリース前の、Place IDのない座標ベースの店舗と架空サンプルは使用しない。既存のローカルデータを整理する場合は以下を実行する。

```sh
# 対象件数だけ確認
pnpm stores:cleanup
# 対象店舗と、その店舗を指すplaceLinksを削除
pnpm stores:cleanup --apply
```

削除対象は`isSample: true`または有効な`googlePlaceId`を持たない店舗。Place IDのある通常店舗、管理者設定、Authアカウントは保持する。処理中に変更されたデータを再確認するトランザクションを使用する。再実行しても対象がなければ削除0件になる。

接続先は`demo-toilet-map`のローカルFirestore Emulator（`127.0.0.1:18081`または`localhost:18081`）に限定する。別プロジェクトや外部ホストを指定すると拒否する。クラウドへの接続は行わない。

Firestoreは18081、Authは19090、[Emulator UI](http://127.0.0.1:14001)は14001を使用する。`pnpm emulators:stop`で正常停止するとDockerボリュームへ保存し、次回起動時に復元する。通常操作ではボリュームを削除しない。

## 取得と表示の範囲

現在地（取得失敗時は東京駅）から半径3kmをgeohashで検索し、範囲外・重複・不正データを除いて距離順に最大100件を表示する。Place IDのない店舗と架空サンプルはスキーマ検証で除外する。候補の省略がある場合は最寄り100件を保証しない。詳細は[周辺検索](../architecture/search.md)を参照する。

更新失敗時は前回の結果を残して案内する。手動の「更新」はFirestoreだけを再取得する。店舗のピン・一覧から詳細を開き、「一覧へ戻る」で解除する。地図の余白をクリックしてもピンや座標は表示しない。

## 検証

```sh
pnpm check
pnpm test:rules:docker
pnpm test:e2e
```

自動テスト用の架空店舗6件は`tests/fixtures/stores.ts`、ローカル開発用の万願寺周辺7件は`scripts/data/stores.json`に置く。Rules・取得・整理・シードの結合テストは専用プロジェクト`demo-toilet-map-tests`を使用し、開発用データを変更しない。空のDBへの投入、再実行、編集済み店舗の保持、不足データの補完、Place IDの競合を検証する。テストではSDKの置き換えや空のキーを使い、有料Maps APIを呼び出さない。

保存形式は[データモデル](../architecture/data-model.md)、権限は[アクセス制御](../architecture/security.md)を参照する。
