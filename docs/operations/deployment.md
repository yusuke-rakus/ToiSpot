# 公開準備と運用

[概要](../../README.md) · [文書一覧](../README.md)

- 利用規約・プライバシーポリシーを公開し、Googleの規約・ポリシーへの必要な参照を含める。
- 地図のロゴ・帰属表示を隠さず、スマホの詳細表示でも重ねて遮らない。
- 情報には確認時点を表示し、現地の最新状況と異なる可能性を利用者に伝える。
- 公開する備考に個人情報や管理用の連絡事項が混ざらないようにする。
- 通知の受信先、超過・障害時の対応者、DBの復旧方法を公開前に決める。
- Firestoreの管理バックアップやPITRは無料枠に含まれないため、自動的に有効化せず、費用と復旧要件を検討する。

出典：[Mapsの公開要件](https://developers.google.com/maps/documentation/javascript/policies)、[Firestoreの無料対象外機能](https://firebase.google.com/docs/firestore/pricing)。

## 現在のローカル設定と公開前の差分

`firebase.json` にHostingのSPAフォールバック、Firestoreルール・インデックス、Auth・Firestore Emulatorを設定済み。クラウド側には反映していない。

Firestoreルールは公開店舗の読み取りと、許可したGoogle管理者の作成・更新を許可する。メール・プロバイダー・確認済み状態と保存データを検証し、削除と管理者設定のクライアント書き込みは禁止する。現在の認証・取得・保存はEmulator限定で、クラウド接続に切り替えた場合は無効になる。本番公開前にQ-04・Q-08〜Q-12の残る仕様、実Google認証、管理者運用と公開接続を確認する。

実プロジェクトのID、請求先、DBリージョン、Google管理者の設定、許可ドメイン、Mapsのキー制限とクォータを決めてから、接続・公開手順を追記する。現時点ではデプロイ用のパッケージスクリプトを設けない。
