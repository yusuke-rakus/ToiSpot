# 要件と初期版の機能

[概要](../../README.md) · [文書一覧](../README.md)

## 目的と確定要件

コンビニのトイレについて、貸してもらえるか、設備がいくつあるか、男女別か、小便器があるかなどを記録し、地図から調べられるアプリを作る。

以下は確定要件とする。

| ID   | 要件                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------- |
| R-01 | スマートフォンとPCのブラウザで使えるWebアプリにする                                                              |
| R-02 | Google MapsのAPIを利用し、新しいFirebaseプロジェクトを用意する                                                   |
| R-03 | 一般利用者はログイン不要で情報を閲覧できる                                                                       |
| R-04 | 一般利用者は新規登録・修正を申請でき、管理者が承認した情報だけを公開する。直接の登録・編集は管理者だけに許可する |
| R-05 | 初期版の管理者は1名。本番・ローカルともメール・パスワード認証とし、管理者UIDで編集権限を制限する                 |
| R-06 | 周辺コンビニをPlacesで表示し、取得した店舗に管理者が確認したトイレ情報を登録する                                 |
| R-07 | 利用可の店舗で男性用・女性用・共用の個室数と、男性用小便器数を記録する                                           |
| R-08 | 請求先登録を許容し、利用制限と監視を設けて無料枠内で月額0円を目指す。超過課金の可能性は残る                      |
| R-09 | UIコンポーネントにshadcn/uiを使用する                                                                            |
| R-10 | CSSにTailwind CSSを使用する                                                                                      |

2026-11-07の指示によりGoogleログインからメール・パスワード認証へ変更した。ローカルはEmulator専用アカウント、本番はConsoleで事前登録したアカウントを使う。一般利用者はログイン不要。管理者は`/admin-login`で認証後、同じ`/`で登録・編集する。

2026-11-11の指示により、管理者以外による新規登録・修正申請を追加する。一般利用者向けログインは追加せず、管理者以外は全員承認待ちとする。管理者の専用画面は申請中だけを表示し、承認・却下に対応する。処理済み履歴や申請内容を修正して承認する機能は設けない。

## 初期版の機能案

この章は、確定要件を具体化するための提案。細部は[未決事項](../decisions/README.md)で決定する。

### 閲覧者の操作

1. 地図を開き、現在地または東京駅周辺のコンビニ（近い最大20件）と登録済み店舗を探す。地図移動後は「この周辺を検索」を押す。
2. 地図のピンまたは一覧から店舗を選ぶ。未登録はグレーの「データなし」、登録情報を確認できない場合は確認中・確認不可として表示する。
3. 貸出可否を確認し、利用可ならアイコン付きの設備数を見る。0の設備は表示せず、未確認は「不明」とする。備考は入力がある場合だけ表示する。
4. 必要に応じて、貸出可否、男女別・共用、小便器の有無で絞り込む。
5. 未登録店舗の登録、または登録済み店舗の情報修正を申請する。承認までは公開情報に反映しない。

位置情報の取得は本人の許可を前提とし、初回描画後と現在地ボタン操作時に要求するものとし、拒否された場合も地図操作で利用できるようにする。利用者の現在地をDBへ保存しない案とする。

### 管理者の操作

1. `/admin-login`で事前登録したメールアドレス・パスワードを入力して認証する。
2. 地図上で店舗の位置を指定し、店名・住所・トイレ情報を入力する。
3. 保存後に公開画面で表示を確認する。
4. 再調査時に貸出状況、利用可の設備数、備考を更新する。
5. ヘッダーのベルから申請一覧を開き、内容を確認して承認・却下する。申請中があるとベルに件数を表示する。画面表示時・手動更新時・審査後に取得し、リアルタイム更新は行わない。

削除・非公開・閉店の操作は、復旧方針を決めてから仕様化する。通信失敗時は入力を保持して再試行できる案とする。

### 初期版では対象外とする提案

- 一般利用者による承認を経ない公開、口コミ、写真アップロード。
- Places検索結果全体の網羅的な自動収集・永続保存（管理者が選択して登録する店舗のPlace ID・店名・住所・座標は保存する）。
- アプリ内での経路計算、ストリートビュー。
- iOS・Androidストアへの配布。
- 複数管理者、一般利用者アカウント、招待制の閲覧。

これらは追加要望があれば再検討する。管理者が記録するトイレ情報を、Google側のデータから自動取得できる前提にはしない。
