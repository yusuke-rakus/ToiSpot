# 周辺検索と読み取りの抑制

[概要](../../README.md) · [文書一覧](../README.md)

## 現在のローカル表示

地図の初回描画後に `navigator.geolocation` で位置情報の許可を要求する。取得できれば現在地、拒否・失敗・非対応の場合は東京駅を中心とする地図を表示し、その表示範囲の登録店舗を検索する。「現在地」ボタンから再取得もできる。位置情報はDB・端末ストレージへ保存しない。

Emulatorの `stores` を `geofire-common` のgeohash範囲で検索する。各範囲から101件まで取得し、101件目は超過判定専用にする。先頭100候補の重複をIDで除き、共有スキーマで検証する。表示範囲内かつ設定された検索半径内の店舗を地図の中心からの距離順（同距離はID順）に並べ、最大100件を地図と一覧へ表示する。不正データの件数を案内する。

各範囲の候補数または一致数が上限を超えた場合は省略を明示する。候補の打ち切りによって最寄り店舗が欠ける可能性があるため、周辺の全件・最寄り100件とは保証しない。絞り込み後0件でも候補の超過があれば「店舗なし」と断定しない。geohashが欠落・実座標と不一致の既存レコードは取得されないことがある。アプリの登録編集は座標からgeohashを生成する。

検索中心の座標と表示境界をQueryキーに含める。初回・現在地や目的地への移動・「この周辺を検索」で取得する。自動モードでは地図の移動・拡大縮小後も検索する。リアルタイム購読も行わない。異なる検索中心の結果を混在させない。Emulatorと設定済みクラウドの両方で取得し、Queryキーには接続モードとプロジェクトIDも含める。設定不備・E2Eモードでは取得しない。詳細は[サンプル表示](../development/sample-data.md)を参照。

## Placesと取得回数

Placesの検索結果全体は画面内だけに保持する。管理者が選択して保存する店舗情報は登録データとして別に扱う。初回は位置情報の結果を待ってから表示範囲を検索し、その後は現在地や目的地への移動・検索ボタン・失敗時の再試行で取得する。Firestoreの更新・保存ではPlacesを再検索しない。紐付け確認はPlace IDごとに別途取得し、再検索ごとに照会し、同じ候補が返っても以前の未登録判定を再利用しない。照会対象が変わったら古い結果を混ぜない。

Placesの表示範囲に応じた検索半径と、設定時の分割取得については[地図画面](map.md#周辺コンビニと登録状況)を参照する。

## 今後の検索機能

範囲外の候補や重複を含む読み取り量から、クラウド料金を試算する。
