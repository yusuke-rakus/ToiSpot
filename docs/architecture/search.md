# 周辺検索と読み取りの抑制

[概要](../../README.md) · [文書一覧](../README.md)

## 現在のローカル表示

地図の初回描画後に `navigator.geolocation` で位置情報の許可を要求する。取得できれば現在地、拒否・失敗・非対応の場合は東京駅を中心に、半径3kmの登録店舗を検索する。「現在地」ボタンから再取得もできる。位置情報はDB・端末ストレージへ保存しない。

Emulatorの `stores` を `geofire-common` のgeohash範囲で検索する。各範囲から101件まで取得し、101件目は超過判定専用にする。先頭100候補の重複をIDで除き、共有スキーマで検証する。実際の距離が3km以内の店舗だけを距離順（同距離はID順）に並べ、最大100件を地図と一覧へ表示する。不正データの件数を案内する。

各範囲の候補数または一致数が上限を超えた場合は省略を明示する。候補の打ち切りによって最寄り店舗が欠ける可能性があるため、周辺の全件・最寄り100件とは保証しない。絞り込み後0件でも候補の超過があれば「店舗なし」と断定しない。geohashが欠落・実座標と不一致の既存レコードは取得されないことがある。アプリの登録編集は座標からgeohashを生成する。

検索中心の座標と半径をQueryキーに含める。初回・現在地の更新・手動更新時に取得する。地図移動・詳細開閉では再取得せず、「この周辺を検索」で地図中心へ変更する。リアルタイム購読も行わない。異なる検索中心の結果を混在させない。クラウドモードでは取得を無効にする。詳細は[サンプル表示](../development/sample-data.md)を参照。

## Placesと取得回数

Placesの検索結果全体は画面内だけに保持する。管理者が選択して保存する店舗情報は登録データとして別に扱う。初回は位置情報の結果を待ってから1回検索し、その後は現在地への移動・検索ボタン・失敗時の再試行で取得する。Firestoreの更新・保存ではPlacesを再検索しない。紐付け確認はPlace IDごとに別途取得し、再検索ごとに照会し、同じ候補が返っても以前の未登録判定を再利用しない。照会対象が変わったら古い結果を混ぜない。

## 今後の検索機能

- Google Placesは半径3km・距離順で近い最大20件を取得済み。「この周辺を検索」は実装済み。
- 検索半径の変更、条件による絞り込み。
- 候補の範囲外・重複を含む読み取り量を考慮したクラウド料金の試算。
