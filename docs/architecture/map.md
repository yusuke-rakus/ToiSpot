# ローカルの地図画面

[概要](../../README.md) · [文書一覧](../README.md) · [技術構成](README.md)

## 実装済みの操作

- Google Maps JavaScript APIを `@vis.gl/react-google-maps` で表示する。
- 現在地取得前・取得失敗時は東京駅付近、ズーム14。表示言語は日本語、地域は日本。
- 地図の移動・拡大縮小と、コンビニのピン選択ができる。地図の余白をクリック・タップすると選択を解除し、スマホの下部シートを閉じる。地図上のカーソルは通常の矢印にする。
- Google Maps標準の操作ボタンは`disableDefaultUI`と`cameraControl: false`で非表示にし、アプリの現在地・一覧ボタンとの重なりを防ぐ。Googleロゴと帰属表示は維持する。
- 地図の操作はGoogle Maps JavaScript APIの標準ジェスチャーを使う。`gestureHandling="greedy"`で1本指の移動・2本指のピンチ操作を受け付け、`isFractionalZoomEnabled`で小数ズームを有効にする。ダブルタップによる拡大も有効にし、スマホ幅では管理者ログインの入口を3回タップに分ける。
- 初回描画後と「現在地」操作時にブラウザで位置情報を要求し、取得できれば現在地へ移動する。移動後の地図の表示範囲からコンビニと登録店舗を取得する。
- 地図画面のヘッダーを撤去して全面へ地図を表示し、テーマ・申請一覧・ログアウトの操作を地図右上へまとめる。検索はスマホでは地図上部中央、PCでは左上のフローティングパネルに配置する。PCの一覧・詳細も検索と同じパネル内に表示し、結果部分だけスクロールさせる。スマホの結果一覧・詳細は同じ下部シートで切り替える。

ローカルFirestoreの登録店舗を取得し、ピンと一覧に表示する。登録店舗とGoogle Placesの候補は店名の先頭からセブン-イレブン、ローソン、ファミリーマートを判定し、該当しない店舗は共通のピンを表示する。SVGは `public/icons/map-pins/` に置く。トイレ情報が「データなし」と確定した店舗には、`neutral/` にある同じ種類のグレーのピンを使う。

ピンまたは一覧から詳細を選ぶと地図を店舗位置へ移動し、同じピンを220msのease-outで1.5倍に拡大する。動きを減らす設定では即座に切り替える。詳細の「一覧へ戻る」ボタンは設けない。スマホは右下の一覧アイコン、PCは地図の余白操作で一覧へ戻り、スマホでは一覧のスクロール位置を復元する。スマホはシートの閉じるボタンまたはEscでも選択を解除できる。店舗の選択や解除でも地図自体は維持する。

Place IDのある登録店舗とGoogle Placesの候補を一覧・詳細へ表示する。一覧は店名・貸出状況・住所・検索地点からの直線距離を表示する。詳細は店舗名・住所・貸出状況を表示する。利用可では共用個室・男性用個室・女性用個室・男性用小便器をアイコン付きの2列で表示し、0の設備は非表示、nullは「不明」とする。全設備が0なら設備表示全体を省く。利用不可では設備表示を省き、備考は入力がある場合だけ表示する。PCは左パネルを使う。スマホ幅（1024px未満）では、結果一覧と選択店舗の詳細を単一の下部シートで切り替える。シートを開いたまま地図を操作でき、別のピンを選ぶと表示を切り替える。貸出状況は「利用可」「利用不可」の2状態で、未登録の「データなし」と区別する。登録店舗は表示範囲を対象として、中心からの距離順に表示する。表示範囲を取得するまでは、東京駅から半径3kmの登録店舗を表示する。

`/admin-login`で管理者がメール・パスワード認証すると、店舗登録・編集の操作を追加する。新規登録はPlacesで取得した未登録コンビニの詳細から行い、Place ID・店名・住所・座標をフォームに引き継ぐ。フォームはDialogとして地図の上へ表示し、閉じる・保存で地図インスタンスを維持する。手順は[管理者機能](../development/admin.md)を参照する。

## フローティング検索UI（2026-11-17）

地図画面ではアプリヘッダー・検索用の帯・スマホの全画面検索ダイアログは設けない。既存ヘッダーの操作ボタンは右上のフローティンググループへ移し、他ページのヘッダーと動作を共通化する。スマホは検索ボックスを上端に置く。手動モードでは「この周辺を検索」をその12px下の中央、その下の右側にテーマ・管理者操作を並べて重なりを避ける。自動モードではテーマ・管理者操作を検索ボックス直下の右側に置く。スマホは検索入力へのフォーカスで同じボックス内に条件行・候補を展開し、PCは条件行を常時表示する。条件行は「利用可のみ」「設備」「チェーン」で構成し、設備とチェーンはshadcnのPopover・Checkboxで複数選択する。Popover内は適用前の変更を一時保持し、クリアも適用時に反映する。検索入力から条件操作へ移っても入力中の文字列を保持し、候補と条件Popoverは同時表示しない。フォーカスや入力待機だけでは店舗一覧・詳細とスクロール位置を維持し、入力受付の案内は表示しない。実際の候補取得・エラー・候補選択中のみ候補領域を一覧の上に追加する。スマホの一覧シートもフォーカスでは閉じない。地図のタップや閉じる操作で検索を折りたたみ、適用条件は維持する。折りたたみ中も条件数から条件行を開ける。

現在地は地図右下の48pxアイコンボタンとし、ホバー・フォーカス時にTooltip「現在地」を表示する。取得中はSpinnerを表示する。スマホではその上に48pxの店舗一覧アイコンを縦に並べ、大きな件数付き一覧バーは設けない。下部シート表示中はResizeObserverで測ったシート上端の12px上へ追従する。候補の表示可能な高さはVisual Viewportの変化に合わせ、キーボード表示時もスクロール可能にする。手動検索ボタンは検索展開中に隠し、通常時はスマホの検索ボックス下、PCのパネル右側の地図上部へ配置する。

店舗一覧ではタイトル・件数・更新操作の見出しセクションを表示しない。検索範囲・件数と下部シート名は読み上げ用に保持し、店舗行から表示する。登録済み店舗の編集・修正申請ボタンは、未登録店舗の登録ボタンと同様に詳細末尾へ配置する。登録情報の再取得は取得失敗時の復旧操作として表示する。

## 場所検索と条件の絞り込み

現在地周辺と行き先の事前検索を同じ画面から使う。駅名・地名・住所・店舗名を1つの欄に入力し、日本国内の場所候補を表示する。候補選択は、その場所の周辺を探す操作とする。店舗名の候補も検索地点として扱い、トイレ情報の詳細を直接開いたり、店舗登録の対象にしたりしない。

場所候補はGoogle Maps JavaScript APIのAutocomplete Data APIで取得する。前後の空白を除いた2文字以上の入力が止まってから750ms後に問い合わせ、日本語IMEの変換中は送信しない。`includedRegionCodes: ['jp']`で日本国内を対象にし、地図付近を優先する`locationBias`を使う。表示範囲への制限は設けず、離れた地域も検索できるようにする。

同じ入力操作ではセッショントークンを共有し、選択・クリア・キャンセルで更新する。選択時は予測オブジェクトの`toPlace()`から`fetchFields({ fields: ['location'] })`を呼び、座標だけを取得する。ラベルとPlace IDは候補を使う。古い入力・選択への応答は無視し、検索履歴・候補・移動先は画面内だけに保持する。候補欄にはGoogleの帰属表示を付け、キーボードの上下・Enter・Escapeと状態の読み上げに対応する。

座標取得後は選択を解除して地図を移動し、移動完了後の表示範囲を検索する。初回の現在地取得が遅れて完了しても、先に選んだ検索地点を上書きしない。座標取得に失敗した場合と入力を取り消した場合は、現在の検索地点・結果を保持する。

条件は以下を使う。初期状態は条件なしとし、地域変更・現在地への移動でも適用済み条件を保持する。

| 条件                                                | 一致する店舗                                                    |
| --------------------------------------------------- | --------------------------------------------------------------- |
| 利用可のみ                                          | 登録情報が「利用可」の店舗                                      |
| 女性用個室・共用個室・男性用個室・男性用小便器      | 利用可かつ選んだ設備のいずれかが正数の店舗。0・nullは一致しない |
| セブン-イレブン・ローソン・ファミリーマート・その他 | 選んだチェーンのいずれか。ピンと同じ店名判定を共通利用する      |

異なる条件群はANDで組み合わせる。条件パネルでは変更を一時保持して適用し、キャンセルでは破棄する。「利用可のみ」は直接切り替えられる。営業時間・車いす対応・おむつ交換台など未収集の情報は備考から推測しない。

条件は登録店舗とPlaces候補の統合後にクライアントで適用し、ピン・一覧・件数に同じ結果を使う。条件変更ではAPI・Firestoreを再取得せず、スキーマ・Rules・インデックスも変更しない。条件から外れた選択店舗は詳細を閉じる。元の取得結果と通信状態は維持し、「条件に一致しない」「店舗がない」「取得失敗」「上限により一部のみ表示」を区別する。検索地点からの距離は直線距離で、徒歩時間や現在地からの距離を示すものではない。

出典：[Autocomplete Data API](https://developers.google.com/maps/documentation/javascript/place-autocomplete-data)、[セッション料金](https://developers.google.com/maps/documentation/javascript/session-pricing?hl=ja)、[Mapsの帰属表示と保存ポリシー](https://developers.google.com/maps/documentation/javascript/policies)、[W3C Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)。

## 環境変数と起動

`.env` または `.env.local` に設定する。`.env.local` などの優先順位に注意し、変更後は開発サーバーを再起動する。キーの値を文書・ソースコード・ログに転記しない。

```dotenv
VITE_USE_FIREBASE_EMULATORS=true
VITE_GOOGLE_MAPS_API_KEY=取得したキー
VITE_GOOGLE_MAPS_MAP_ID=DEMO_MAP_ID
```

Map IDを省略した場合は開発用の `DEMO_MAP_ID` を使用する。APIキーとは別の設定。通常キーではMaps JavaScript APIとPlaces API（New）を同じプロジェクトで有効化し、キーのAPI制限に両方を含め、開くローカルURLをHTTPリファラー制限で許可する。キーが地図表示だけに対応していると、地図は表示できてもコンビニ検索は失敗する。起動コマンドは `pnpm dev`。

店舗表示には `pnpm emulators`・`pnpm seed` を実行する。Firebaseの実プロジェクトは不要。Emulator接続失敗時も地図を操作でき、更新ボタンで再取得できる。`VITE_USE_FIREBASE_EMULATORS=false`では店舗取得を無効にする。Mapsには実際に接続し、通常のAPIキーではローカル利用も利用量に含まれる。

試作には、対象となる個人Googleアカウントで請求先登録なしに取得できるMaps Demo Keyも利用できる。機能と日次使用量に制限があり、本番公開用のキーではない。

出典：[Mapsのキー設定](https://developers.google.com/maps/documentation/javascript/get-api-key)、[Maps Demo Key](https://developers.google.com/maps/documentation/javascript/demo-key)、[開発用Map ID](https://developers.google.com/maps/documentation/javascript/advanced-markers/start)。

自動検索を利用する場合は、次の公開設定を追加する。未設定の場合は「この周辺を検索」で地図操作後の表示範囲を検索する。変更後は開発サーバーを再起動し、本番では再ビルド・再デプロイする。

```dotenv
VITE_PLACES_AUTO_SEARCH=true
VITE_PLACES_EXPANDED_SEARCH=true
VITE_PLACES_MIN_ZOOM=13
VITE_PLACES_MAX_RESULTS=100
VITE_PLACES_MAX_REQUESTS=9
```

| 設定                          | 未設定時 | 意味                                                        |
| ----------------------------- | -------- | ----------------------------------------------------------- |
| `VITE_PLACES_AUTO_SEARCH`     | `false`  | 地図の移動・拡大縮小後に自動で検索                          |
| `VITE_PLACES_EXPANDED_SEARCH` | `true`   | 自動モードで20件に達した領域を分割して追加検索              |
| `VITE_PLACES_MIN_ZOOM`        | `13`     | 自動モードで取得を許可する最小ズーム。0～22の整数           |
| `VITE_PLACES_MAX_RESULTS`     | `100`    | Placesの最大件数。正の安全な整数                            |
| `VITE_PLACES_MAX_REQUESTS`    | `9`      | 1回の分割検索のPlaces最大要求数。親領域を含む正の安全な整数 |

真偽値は`true`・`false`を使う。未設定・空欄・不正値は各初期値へ戻し、件数・要求数に無制限指定は設けない。手動モード、分割取得を`false`にした自動モード、要求上限を1にした自動モードでは、1要求で設定件数と20件の小さい方まで取得する。上限はPlacesに適用し、Firestoreの周辺取得上限100件と紐付け照会は別に扱う。

## 状態管理とデータの扱い

- `src/features/map/map-page.tsx` が地図画面、`map-config.ts` が設定と初期位置を担当する。
- APIProviderを1つにし、カメラ状態はReactで保持する。店舗選択では`panTo`で地図を店舗へ寄せ、詳細と強調表示を更新する。
- `reuseMaps` を有効にし、同じMap IDの再マウント時に再利用を試みる。ログイン画面から戻るとき、描画済みの地図を再利用できればタイルの描画完了通知を待たずに表示する。無制限の無料表示を保証するものではない。
- 現在地・場所候補・検索地点は画面内の状態だけに保持し、検索履歴としてDB・端末ストレージには保存しない。現在地取得や場所検索で地図を移動すると、その地域の地図をGoogleから読み込む。
- Places API（New）のNearby Searchでコンビニを取得し、Autocomplete Data APIとPlace Detailsで検索地点を解決する。Geocoding API・Routes APIは使用しない。管理者が選択して登録した店舗に限り、Place ID・店名・住所・座標と入力したトイレ情報をFirestoreに保存する。
- 店舗の取得は `src/features/stores/` に集約し、TanStack Queryで結果を共有する。読み込み・0件・接続失敗・不正データ・検索候補・表示の上限超過を区別する。仕様と投入方法は[店舗データ](../development/sample-data.md)を参照する。

出典：[APIProvider](https://visgl.github.io/react-google-maps/docs/api-reference/components/api-provider)、[地図コンポーネント](https://visgl.github.io/react-google-maps/docs/api-reference/components/map)。

## 読み込みと失敗時

| 状態                                 | 挙動                                                                   |
| ------------------------------------ | ---------------------------------------------------------------------- |
| キー未設定                           | 設定案内を表示し、Mapsを読み込まない                                   |
| 読み込み中                           | タイル描画まで読み込み表示。現在地ボタンを無効にする                   |
| 20秒以上の待機                       | 通信・設定の確認と手動の再読み込みを案内。後から描画できれば地図へ戻る |
| SDK読み込み失敗                      | 通信・ブラウザ設定の確認と手動再読み込みを案内                         |
| 認証失敗                             | キー・API有効化・アクセス元制限の確認を案内                            |
| 位置情報拒否・取得失敗・タイムアウト | エラーを案内し、地図移動とコンビニ選択を継続可能にする                 |

位置情報のタイムアウトは10秒、直近1分の取得結果の再利用を許可し、高精度取得は要求しない。初回描画後の自動取得は1回だけ行う。地図の自動再読み込みは行わない。Mapsのエラー本文はキーを含む可能性があるためアプリからログへ出力しない。

## 検証方法

`pnpm check` と `pnpm test:e2e` で検証する。単体テストは地図SDK・位置情報を置き換えて、実キーや実際の現在地を使わずに操作を検証する。

Playwrightのテストサーバーは `e2e` モードでキーを空に上書きし、既存の開発サーバーを再利用しない。個人の `.env` にキーがあっても有料Maps APIを自動テストから呼び出さない。実キーでの表示とピン操作はローカル画面で別途確認する。

場所検索は750msの入力待機、IME変換中の抑止、古い応答の無視、候補選択時の1回の地域検索、現在地取得との競合、座標取得失敗をSDKのスタブで確認する。条件検索は0・null・正数、ORとANDの組み合わせ、未登録・取得失敗、ピンと一覧・件数の一致、条件変更で追加通信がないことを確認する。PC・スマホの明暗テーマで一覧と詳細の往復、キーボード操作、状態の読み上げも確認する。

## 周辺コンビニと登録状況

初回は位置情報の取得後、現在地（失敗時は東京駅）周辺の表示範囲を検索する。現在地ボタンや場所候補でも移動先の表示範囲を検索する。手動モードでは地図を移動・拡大縮小した後、「この周辺を検索」を押して表示範囲を更新する。

自動モードでは地図の移動・拡大縮小が止まって300ms後に表示範囲を更新する。これは場所候補の750ms待機とは別の処理とする。PlacesとFirestoreは同じ中心・表示境界を使う。Firestoreは範囲を覆うgeohashから取得し、表示境界外・重複・不正データを除く。検索範囲をキャッシュキーへ含め、別の範囲の古い応答が現在の結果を上書きしないようにする。店舗選択のための移動・テーマ変更・同じ範囲の重複通知・条件の絞り込みでは再検索しない。Placesだけの再試行も利用できる。

Nearby Searchの上限は1要求20件・半径50km。1要求で検索する場合は、地図の中心から表示範囲の最も近い辺までの距離を使い、半径50kmまでに抑える。地図の回転・傾斜操作を無効にして、検索円が表示範囲に収まるようにする。Firestoreも同じ半径で取得し、表示範囲内の店舗に絞る。分割取得を有効にした自動モードで2要求以上を許可している場合は、20件に達した領域を4分割し、50kmを超える領域は送信前に分割する。表示境界外を除き、Place IDで重複を除く。一覧は地図の中心からの距離順で表示する。

再取得中・失敗時は前回結果を残す。一部失敗は取得できた結果と失敗の案内を併記し、全失敗・0件と区別する。自動モードで最小ズーム未満になると待機中の処理・再試行・登録情報の取得を止め、前回のピン・一覧・選択した詳細を維持する。最小ズーム以上に戻ると最新範囲を検索する。送信済み通信は取り消せないため応答を無視し、その通信も含めPlacesは同時2要求までに制限する。

登録済み店舗は別途最大100件を取得し、Places候補に含まれなくても表示する。Places候補ごとの`placeLinks/{placeId}`と紐付け先店舗は範囲・100件制限と独立して照会し、同じ登録店舗を1本のピン・1行の一覧へ統合する。取得中・失敗・Emulator無効では「データなし」と断定しない。紐付け済み情報は古い内容が残る場合があるため、取得失敗の案内と更新操作を表示する。

検索中の同じ検索条件への要求を重複させず、自動再試行しない。新しい検索や画面終了後に返った古い結果は無視する。Places失敗でも登録店舗を表示し、コンビニ検索だけ再試行できる。取得停止中を除き、「更新」と保存後の再取得はFirestoreだけを更新し、Places検索を増やさない。

Google提供の情報はラベルと境界線・余白でアプリのトイレ情報と区別し、返された提供元表示も表示する。地図の帰属表示を遮らない。公開前には利用規約・プライバシーポリシーと最新のGoogle要件を整える。

出典：[Nearby Search](https://developers.google.com/maps/documentation/javascript/nearby-search)、[Nearby Searchの上限](https://developers.google.com/maps/documentation/places/web-service/reference/rpc/google.maps.places.v1#searchnearbyrequest)、[Placesのポリシー](https://developers.google.com/maps/documentation/places/web-service/policies)。

## テーマとの連動

解決済みのテーマを地図の`colorScheme`（`LIGHT` / `DARK`）へ渡す。配色変更でSDK内部の地図インスタンスが交換されるため、中心・ズーム・傾き・方角をReactで保持して引き継ぐ。`reuseMaps`で色別のインスタンス再利用を試みるが、新規生成に伴う課金を回避できる保証はない。

テーマ変更では店舗選択・編集内容を維持し、選択店舗への再移動・現在地の再取得・PlacesやFirestoreの再検索を行わない。読み込み中の現在地取得が完了した場合は、最新の地図に反映する。

出典：[地図コンポーネントの配色と再利用](https://visgl.github.io/react-google-maps/docs/api-reference/components/map)。
